# 果园管理系统

果园（地块 / 果树 / 采摘批次 / 库存）的台账与采摘入库管理。基于 Spring Boot 3.3 + Vue 3 + MySQL + Redis，docker compose 一键启动。

## 启动

```bash
./start.sh
```

启动后访问 http://127.0.0.1:8241/ 。

## 模块

- 地块：果园分区台账，展示在产株数（未清树现算），停用前需清空在管果树
- 果树：果树档案，归属地块、品种、健康状态；病弱树开清树单后即「已清」——地块在产株数立刻减一、
  不能再选入新采摘批次；树若还挂在待采/采集中的批次上，清树被拦截并指明是哪条批次未入仓；
  已入仓库存不随清树/撤回加减；清树单可撤回，株数加回，但撤回前已从批次摘掉的树不自动加回、
  不把批次改回可推；同一棵树并发清树只留一笔，另一笔报清原因
- 施药记录：按地块登记药名、施药日与安全间隔天数，可作废；停用地块不许补记
- 采摘批次：按地块按日的采摘登记，状态机 待采→采集中→已入仓；开单可勾选本地块在产果树，
  未入仓批次可摘掉果树、已入仓批次名单冻结；
  间隔未满的地块不能新开批次；施药日不晚于批次采摘日且间隔未满的药单会卡住该批次推进，
  解禁或作废后自动放行；已入仓批次与库存公斤数不受事后补药影响；
  入仓时实际产量超过预估直接被拦，库存一行都不动；
  已入仓批次事后可在采摘页改品种、改实际公斤，库存逐笔对账：改品种把这一笔入仓公斤从旧品种
  划转到新品种（旧扣新加同一笔），改实际公斤只跟差额走且调大不超过入仓时预估；
  同一批次并发两笔调账只许一笔成功，后到的必须看到最新账（版本号 CAS）再报失败，不会两笔都加减
- 库存：按品种累计产量与出库，低于预警线提示
